<task type="auto">
  <name>Task 1: Create comparison route with loader and dual-radar chart</name>
  <files>app/routes/division/compare.tsx</files>
  <action>
Create `app/routes/division/compare.tsx` with the following:

**Loader:**
1. Parse `players` URL search param (comma-separated IDs, e.g., `?players=player-001,player-002`). If fewer than 2 valid IDs, redirect to `/division/players`.
2. Parse weight params using existing `parseWeightParams(request)` from `~/lib/scoring/player-average`.
3. Fetch both players via `getPlayerById()` and their reports via `getReportsByPlayer()` in parallel (Promise.all).
4. If either player not found, throw 404 Response.
5. Compute `PonderatedAverages` for each player using `calculatePonderatedAverages(reports, boostedAttrs)`.
6. Return: `{ playerA, playerB, averagesA, averagesB, boostedAttrs }`.

**Component:**
1. Back link to `/division/players` ("← Voltar aos jogadores").
2. Page title: "Comparação" with both player names (e.g., "Player A vs Player B").
3. `AttributeToggle` component at top (reuse existing, pass `boostedAttrs`) so weights can be adjusted live in comparison view.
4. Global averages display: Show both players' simple average and ponderated average (when weights active) prominently above the radar. Format: two columns side by side, each showing player name, simple avg, ponderated avg (if weights active).
5. Single `RadarChart` (from Recharts) with two overlaid `<Radar>` elements:
   - Player A: `stroke="var(--color-fm-accent, #2563eb)"`, `fill="var(--color-fm-accent, #2563eb)"`, `fillOpacity={0.3}`
   - Player B: `stroke="#ef4444"`, `fill="#ef4444"`, `fillOpacity={0.2}`
   - Same chart data structure as `player-scores.tsx`: `RADAR_KEYS.map(key => ({ attribute: ATTRIBUTE_LABELS[key], playerA: averagesA.attributes[key] ?? 0, playerB: averagesB.attributes[key] ?? 0 }))`
   - Include `PolarGrid`, `PolarAngleAxis`, `PolarRadiusAxis` (domain [1,5], ticks [1,2,3,4,5]) matching existing player-scores pattern.
   - `ResponsiveContainer` with height={400} for larger comparison view.
6. Legend below radar: two colored dots with player names (blue = Player A, red = Player B).
7. ErrorBoundary: "Jogador não encontrado" with link back to player list (follow pattern from `players.$id.tsx`).

**pt-BR translations:** All user-facing text in Brazilian Portuguese, consistent with existing routes.

Create `app/components/comparison-delta-table.tsx` — a per-attribute comparison table placed below the radar chart in the comparison view.

**Props interface:**
```typescript
interface ComparisonDeltaTableProps {
  averagesA: PonderatedAverages;
  averagesB: PonderatedAverages;
  playerAName: string;
  playerBName: string;
}
```

**Table structure:**
- Columns: Atributo | Player A | Player B | Delta (A−B)
- Rows: All 12 ATTRIBUTE_KEYS in order (pace through workRate)
- Header row with gray background (`bg-gray-50 dark:bg-fm-card-alt`), uppercase labels

**Delta calculation:**
- For each attribute key: `delta = (averagesA.attributes[key] ?? null) - (averagesB.attributes[key] ?? null)`
- If either value is null: show "—" in all three value columns, gray text
- If both values exist: show delta = A − B, formatted to 2 decimal places
- Delta color coding:
  - Positive (A > B): `text-green-600 dark:text-green-400` with "+" prefix
  - Negative (A < B): `text-red-600 dark:text-red-400`
  - Zero (within 0.005): `text-gray-400 dark:text-fm-text-muted`

**Row styling:**
- Alternating row backgrounds for readability (even rows: `bg-white dark:bg-fm-card`, odd rows: `bg-gray-50/50 dark:bg-fm-card-alt/50`)
- Attribute labels from `ATTRIBUTE_LABELS`
- Null values show "—" (em dash) in all columns, per CONTEXT.md decision

**Integration:** Import and render this component in the comparison route (compare.tsx) below the radar chart and legend. Wrap in a section with heading "Comparação por Atributo".

**Do NOT:** Create a new scoring function — reuse existing `PonderatedAverages.attributes` directly. Do not round attribute values in the table cells — show to 2 decimal places.

**app/routes/division/decisions.ts** — Create action route (no loader needed):

```typescript
import { type Route } from "./+types/decisions";
import { json } from "react-router";
import { getDivisionUserIdFromCookie } from "../../cookies.server";
import { setPlayerDecision, clearPlayerDecision } from "../../data/data";
import type { DecisionStatus } from "../../data/types";

export async function action({ request }: Route.ActionArgs) {
  const formData = await request.formData();
  const action = formData.get("_action") as "set" | "clear";
  const playerId = formData.get("playerId") as string;
  const userId = await getDivisionUserIdFromCookie(request);

  if (!userId) {
    return json({ error: "Division user identity required" }, { status: 401 });
  }

  if (action === "set") {
    const status = formData.get("status") as DecisionStatus;
    const result = await setPlayerDecision({ playerId, status, userId });
    return json({ decision: result.decision });
  }

  if (action === "clear") {
    await clearPlayerDecision(playerId, userId);
    return json({ decision: null });
  }

  return json({ error: "Invalid action" }, { status: 400 });
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Action Route | Untrusted FormData with playerId, status, _action crosses here |
| Action Route → DB | Server-side code executes SQL with user-supplied values |
| Cookie → Identity | division-user-id cookie can be spoofed by client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | decisions.ts action route | mitigate | Validate `_action` is exactly "set" or "clear"; validate `status` against decisionStatusSchema before passing to data layer |
| T-10-02 | Spoofing | division-user-id cookie | accept | Cookie-based identity is v1 limitation; no PII at risk; resolved by Supabase auth migration |
| T-10-03 | Information Disclosure | getAllPlayerDecisions in loader | mitigate | Only return decisions (not user IDs) to client; decisionMap is Record<playerId, status> — no userId exposed |
| T-10-04 | Tampering | player-list.tsx onDecisionChange | mitigate | Client-side fetch is convenience only; server-side action route re-validates all input via Zod schemas in data layer |
| T-10-05 | Repudiation | decision_history table | mitigate | Every decision change inserts a history entry with userId + timestamp; audit trail is immutable (no UPDATE/DELETE on decision_history) |
</threat_model>

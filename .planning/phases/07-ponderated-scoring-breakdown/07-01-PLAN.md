  <action>
Extend `app/lib/scoring/player-average.ts` with three new exports:

**1. `PonderatedAverages` interface** — extends `PlayerAverages`:
```typescript
export interface PonderatedAverages extends PlayerAverages {
  ponderatedGlobalAverage: number | null;
  boostedAttributes: string[];
}
```

**2. `parseWeightParams(request: Request): string[]`** — reusable utility for loaders:
- Parse `new URL(request.url).searchParams.get("w")`
- Split by comma, trim, validate each key against `ATTRIBUTE_KEYS` allowlist (filters out unknown/malformed keys — V5 input validation)
- Return filtered array of valid attribute keys

**3. `calculatePonderatedAverages(reports: Report[], boostedAttrs: string[]): PonderatedAverages`**:
- Call `calculatePlayerAverages(reports)` to get base simple averages
- Build weights map: 3 for boosted attributes, 1 for all others (per D-02 fixed 3x multiplier)
- For each of the 12 ATTRIBUTE_KEYS:
  - If `base.attributes[key]` is null → set ponderatedAttributes[key] = null, skip (null exclusion per project convention)
  - If non-null → `ponderatedSum += attrValue * weight`, `ponderatedCount += weight`
- Compute `ponderatedGlobalAverage = ponderatedCount > 0 ? ponderatedSum / ponderatedCount : null`
- Clamp result to [1, 5] range as safety: `Math.max(1, Math.min(5, result))`
- Return `{ ...base, ponderatedGlobalAverage, boostedAttributes: boostedAttrs }`

CRITICAL: The weighted denominator is `sum(weights for non-null attributes only)`, NOT `sum(all 12 weights)`. A player with 8 observed attributes and 4 null should have denominator = sum of weights for those 8 only. This prevents artificial deflation when attributes are "not observed" (Pitfall 1 from RESEARCH.md).

Export `ATTRIBUTE_KEYS` as a const array so other modules can validate against it:
```typescript
export const ATTRIBUTE_KEYS = [...] as const;
```
(If not already exported — currently it's `const` without `export`.)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL params → loader | Untrusted `?w=` parameter enters server-side computation via `request.url` |
| Toggle UI → URL params | Client-side checkbox state writes to URL via `setSearchParams` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | `parseWeightParams()` in player-average.ts | mitigate | Validate each parsed key against `ATTRIBUTE_KEYS` allowlist; silently ignore unknown keys (e.g., `?w=../../../etc/passwd` produces empty array) |
| T-07-02 | Injection | `attribute-toggle.tsx` rendering ATTRIBUTE_LABELS | mitigate | React auto-escapes all rendered content; `ATTRIBUTE_LABELS` is a hardcoded const — no user-controlled input reaches DOM |
| T-07-03 | Availability | URL param string length | accept | Browser-enforced URL length limits (~2000 chars); only 12 known keys possible, max string ~80 chars — no practical DoS vector |
</threat_model>

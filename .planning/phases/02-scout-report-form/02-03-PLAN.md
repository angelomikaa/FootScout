**Part A: Create `app/components/scout-report-form.tsx`**

This is the main form orchestrator implementing the single useForm wizard pattern (RESEARCH.md Pattern 1), RHF→React Router action bridge (Pattern 2 with useSubmit), and step navigation with trigger() validation.

```typescript
import { useState } from "react";
import { useForm, type UseFormRegister } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { useSubmit, useNavigation } from "react-router";
import clsx from "clsx";
import type { Player, Scout } from "~/data/types";
import {
  reportFormSchema,
  type ReportFormValues,
  STEP_FIELDS,
  STEP_LABELS,
  TOTAL_STEPS,
} from "~/data/form-schema";
import { StepIndicator } from "./step-indicator";
import { AttributeRatingRow } from "./attribute-rating-row";
import { PlayerCombobox } from "./player-combobox";
import { NewPlayerFields } from "./new-player-fields";
```

Key implementation details:

1. **useForm setup** — Single form for entire wizard per RESEARCH.md Pattern 1:
   ```typescript
   const form = useForm<ReportFormValues>({
     resolver: zodResolver(reportFormSchema),
     defaultValues: {
       isNewPlayer: false,
       // When isNewPlayer=false, RHF needs all fields registered but
       // new-player fields won't trigger errors because discriminatedUnion
       // only validates the matching branch
       playerId: "",
       scoutId: "",
       matchDate: "",
       opponent: "",
       competition: "",
       matchResult: "",
       physical: { pace: null, strength: null, stamina: null, agility: null },
       technical: { finishing: null, passing: null, dribbling: null, firstTouch: null },
       tactical: { positioning: null, awareness: null, decisionMaking: null, workRate: null },
       matchNotes: { attitude: null, coachability: null, intensity: null, impact: null, notes: "" },
     },
   });
   ```
   CRITICAL: All attribute defaults are `null` per Pitfall 8/D-03. NEVER default to 3.

2. **Step state and navigation** — Per D-01 (wizard), D-02 (block on invalid):
   ```typescript
   const [currentStep, setCurrentStep] = useState(0);

   const handleNext = async () => {
     // Step 0 has conditional validation based on isNewPlayer (Pitfall 5)
     if (currentStep === 0) {
       const isNewPlayer = form.getValues("isNewPlayer");
       if (isNewPlayer) {
         const playerValid = await form.trigger([
           "playerName", "playerDateOfBirth", "playerPositionGroup",
           "playerPosition", "playerClub", "playerNationality", "playerPreferredFoot",
         ]);
         if (!playerValid) return;
       } else {
         const playerValid = await form.trigger("playerId");
         if (!playerValid) return;
       }
       const scoutValid = await form.trigger("scoutId");
       if (scoutValid) setCurrentStep(1);
       return;
     }
     // Steps 1-4: validate step fields with trigger()
     const fieldsToValidate = STEP_FIELDS[currentStep] as unknown as string[];
     const isValid = await form.trigger(fieldsToValidate);
     if (isValid) setCurrentStep((prev) => Math.min(prev + 1, TOTAL_STEPS - 1));
   };

   const handleBack = () => {
     // D-02: Back does NOT validate — only forward advance is blocked
     form.clearErrors(); // Clean up previous step errors per Pitfall 1
     setCurrentStep((prev) => Math.max(prev - 1, 0));
   };
   ```

3. **RHF → React Router action bridge** — Per RESEARCH.md Pattern 2 (useSubmit approach):
   ```typescript
   const submit = useSubmit();
   const navigation = useNavigation();
   const isSubmitting = navigation.state === "submitting";

   const onValidSubmit = (data: ReportFormValues) => {
     const formData = new FormData();
     formData.append("intent", data.isNewPlayer ? "create-player-and-report" : "create-report");

     // Common fields
     formData.append("scoutId", data.scoutId);
     formData.append("matchDate", data.matchDate);
     formData.append("opponent", data.opponent);
     formData.append("competition", data.competition);
     if (data.matchResult) formData.append("matchResult", data.matchResult);

     if (data.isNewPlayer) {
       formData.append("playerName", data.playerName);
       formData.append("playerDateOfBirth", data.playerDateOfBirth);
       formData.append("playerPositionGroup", data.playerPositionGroup);
       formData.append("playerPosition", data.playerPosition);
       formData.append("playerClub", data.playerClub);
       formData.append("playerNationality", data.playerNationality);
       formData.append("playerPreferredFoot", data.playerPreferredFoot);
       if (data.playerHeight) formData.append("playerHeight", String(data.playerHeight));
       if (data.playerWeight) formData.append("playerWeight", String(data.playerWeight));
     } else {
       formData.append("playerId", data.playerId);
     }

     // Flatten nested attribute objects using dot-notation keys
     for (const [key, value] of Object.entries(data.physical)) {
       formData.append(`physical.${key}`, String(value ?? "null"));
     }
     for (const [key, value] of Object.entries(data.technical)) {
       formData.append(`technical.${key}`, String(value ?? "null"));
     }
     for (const [key, value] of Object.entries(data.tactical)) {
       formData.append(`tactical.${key}`, String(value ?? "null"));
     }
     for (const [key, value] of Object.entries(data.matchNotes)) {
       if (key === "notes") {
         if (value) formData.append(`matchNotes.${key}`, String(value));
       } else {
         formData.append(`matchNotes.${key}`, String(value ?? "null"));
       }
     }

     submit(formData, { method: "post" });
   };
   ```

4. **isNewPlayer toggle** — Managed via Controller or a simple button that calls `form.setValue("isNewPlayer", true/false)`:
   ```typescript
   const isNewPlayer = form.watch("isNewPlayer");
   const handleSelectNew = (searchText: string) => {
     form.setValue("isNewPlayer", true);
     form.setValue("playerName" as any, searchText); // Pre-fill name from search
   };
   const handleSelectExisting = () => {
     form.setValue("isNewPlayer", false);
     // Clear new player fields
     form.setValue("playerName" as any, "");
     // ... clear other player fields
   };
   ```

5. **Step rendering** — Conditional render based on currentStep:
   - Step 0: Scout select dropdown (`<select {...form.register("scoutId")}>` with scouts list), PlayerCombobox, isNewPlayer toggle, NewPlayerFields (if isNewPlayer)
   - Step 1: 4 AttributeRatingRow components for physical attributes (pace, strength, stamina, agility)
   - Step 2: 4 AttributeRatingRow components for technical attributes (finishing, passing, dribbling, firstTouch)
   - Step 3: 4 AttributeRatingRow components for tactical attributes (positioning, awareness, decisionMaking, workRate)
   - Step 4: 4 AttributeRatingRow for matchNotes attributes (attitude, coachability, intensity, impact), plus register() text inputs for matchDate (type="date"), opponent, competition, matchResult, and matchNotes.notes (textarea)

   Attribute labels map:
   - Physical: "Pace", "Strength", "Stamina", "Agility"
   - Technical: "Finishing", "Passing", "Dribbling", "First Touch"
   - Tactical: "Positioning", "Awareness", "Decision Making", "Work Rate"
   - Match Notes: "Attitude", "Coachability", "Intensity", "Impact"

6. **Navigation buttons** — Per D-01:
   - Back button: visible on steps 1-4, calls handleBack, type="button"
   - Next button: visible on steps 0-3, calls handleNext, type="button"
   - Submit button: visible on step 4, calls form.handleSubmit(onValidSubmit), type="button", disabled when isSubmitting

7. **Layout structure** — Following welcome.tsx container pattern:

   ```tsx
     <h1 className="text-2xl font-bold mb-6">Scout Report</h1>
     <StepIndicator currentStep={currentStep} steps={STEP_LABELS} totalSteps={TOTAL_STEPS} />
     <div className="mt-6 rounded-2xl border border-gray-200 p-6 dark:border-gray-700 space-y-4">
       {/* Current step content */}
     </div>
     <div className="mt-4 flex justify-between">
       {/* Navigation buttons */}
     </div>
   </main>
   ```

## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| Browser form → useSubmit → Route Action | Client-side RHF validation is convenience only; server-side Zod re-validation in action is the security boundary |
| Route Action → Data Layer | createReport() validates FK refs; createPlayer() validates with Zod schema |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | useSubmit FormData | mitigate | Server-side action re-validates all fields with reportFormSchema.parse() before data layer writes; client validation is UX only |
| T-02-07 | Repudiation | Report submission | accept | No auth in v1; scout identity from dropdown is trust-based (internal tool). Deferred to auth phase |
| T-02-08 | Denial of Service | JSON file writes | accept | Single-user internal tool; no concurrent write protection needed at v1 scale |
</threat_model>

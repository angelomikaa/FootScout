**File 1: `app/components/attribute-rating-row.tsx`**

Create the Controller-wrapped button group component implementing D-07 (numbered buttons 1-5), D-08 (N/O toggle deselects rating, sets null), D-09 (row-per-attribute layout: label left, buttons + N/O right).

This component is a generic that accepts any RHF form values type so it can work with ReportFormValues. The key behaviors:
- Uses `Controller` from react-hook-form with `name` and `control` props
- Renders 5 numbered buttons (1 2 3 4 5), each calls `onChange(n)` on click
- Renders N/O button that calls `onChange(null)` — this deselects any rating per D-08
- Selected rating button gets distinct styling (bg-blue-600 text-white), unselected get bg-gray-100
- N/O button gets distinct styling when active (bg-gray-700 text-white) vs inactive (bg-white border-gray-300)
- Shows inline error message from fieldState.error if present
- Uses `clsx` for conditional class merging
- Each button has `type="button"` (NOT "submit") to prevent form submission
- `aria-pressed` on each button for accessibility
- `aria-label` with descriptive text on each button

Props interface:
```typescript
interface AttributeRatingRowProps<T extends FieldValues> {
  name: Path<T>;
  label: string;
  control: Control<T>;
}
```

Implementation follows RESEARCH.md Pattern 3 and PATTERNS.md `attribute-rating-row.tsx` section exactly. The Controller render function receives `{ field: { onChange, value }, fieldState: { error } }`. The `value` is `1|2|3|4|5|null` matching `attributeScoreSchema`.

CRITICAL: N/O button onClick must call `onChange(null)` — this is what makes null explicit per D-08 and Phase 1 D-03. When N/O is pressed, any numbered rating is visually deselected because `value === null` is true, so no numbered button matches.

**File 1: `app/components/player-combobox.tsx`**

Create the search-as-you-type player selector implementing D-05 (combobox/autocomplete) and D-04 (inline expansion trigger when no match).

Props interface:
```typescript
interface PlayerComboboxProps {
  players: Player[];
  control: Control<ReportFormValues>;
  onSelectNew: (searchText: string) => void;
  error?: string;
}
```

Key behaviors (per RESEARCH.md Pattern 4 and PATTERNS.md `player-combobox.tsx` section):
- Uses RHF `Controller` with `name="playerId"` and `control`
- Local state: `inputValue` (string for display text), `isOpen` (dropdown visibility), `activeIndex` (keyboard highlight)
- Filtering: `players.filter(p => p.name.toLowerCase().includes(inputValue.toLowerCase()))`
- Dropdown shows "{player.name} — {player.club}" per PATTERNS.md display pattern
- Click outside closes dropdown via useEffect + mousedown listener on document
- When no match and inputValue.length > 0: show "Create '{inputValue}' as new player" option that calls `onSelectNew(inputValue)`
- Keyboard navigation: ArrowDown/ArrowUp change activeIndex, Enter selects player at activeIndex, Escape closes dropdown
- Selecting a player: calls `onChange(player.id)` (sets RHF playerId), sets `inputValue` to `player.name`, closes dropdown
- WAI-ARIA attributes on the input: `role="combobox"`, `aria-expanded`, `aria-autocomplete="list"`, `aria-controls="player-listbox"`, `aria-activedescendant`
- WAI-ARIA attributes on the list: `role="listbox"`, `id="player-listbox"`
- WAI-ARIA attributes on each option: `role="option"`, `aria-selected`
- Pitfall 4 avoidance: When navigating back to step 0, reinitialize inputValue from the selected player name using `form.watch("playerId")` + useEffect lookup. This requires receiving `watchedPlayerId` and `players` as props, or the parent can pass the initial display value. Simplest: accept an `initialDisplayName` prop that the parent derives from the current playerId + players list.
- SSR hydration safety (Pitfall 6): Initialize isOpen=false, inputValue="" — these match between server and client.

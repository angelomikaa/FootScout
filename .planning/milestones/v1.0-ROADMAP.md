# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-05-15
**Phases:** 1-8
**Total Plans:** 18

## Overview

FootScout v1.0 delivers a complete U15 youth scouting dashboard. Scouts submit detailed player observations through a staged form; the system calculates simple and ponderated averages, visualizes them as radar charts, and enables side-by-side player comparison. The weighted scoring engine — the core differentiator — lets the division shift scoring weights to match what they're looking for, with transparent breakdowns showing why the ponderated score differs from the simple average.

## Phases

### Phase 1: Data Foundation

**Goal**: Player and report data can be stored, retrieved, and validated through a typed async interface
**Depends on**: Nothing (first phase)
**Requirements**: DATA-01, DATA-02, DATA-03, DATA-04, DATA-05
**Plans**: 1 plan

Plans:

- [x] 01-01: Define Zod schemas/types + async JSON data layer with sample data

Zod-validated TypeScript types for Player, Report, Scout with strict validation. Position enums, preferred foot enum, ISO nationality codes. Attributes rated 1-5 or null (never treated as 3). Async CRUD layer with foreign key validation. Sample data: 3 players, 5 reports, 2 scouts.

## Milestone Summary

**Key Decisions:**

- Decision: JSON file data layer (Rationale: Simple v1, swap to Supabase later)
- Decision: Attributes rated 1-5 or null — null never treated as 3 (Rationale: Prevents lazy middle values)
- Decision: Custom weights per search via URL params (Rationale: Position needs vary dynamically)
- Decision: Score breakdown ships WITH ponderated engine (Rationale: Transparency is the product)
- Decision: Staged form with single useForm (Rationale: Simpler state management across steps)
- Decision: Cookie-based scout identity with 7-day expiry (Rationale: D-13 requirement)

**Issues Resolved:**

- Scout identity cookie (`setScoutIdCookie`) now called on report submit and draft save
- Reports table player names now clickable links to player profiles
- Search placeholder and filter labels translated to pt-BR
- Home page phase badges updated to reflect all 8 phases complete

**Technical Debt Incurred:**

- Radar chart shows same shape for simple vs ponderated (per-attribute averages are identical; only global weighting changes — mathematically correct, but could add a second radar overlay for ponderated values)
- JSON file data layer — will need migration to Supabase for production scale
- No Nyquist validation files created for any phase (VALIDATION.md missing)
